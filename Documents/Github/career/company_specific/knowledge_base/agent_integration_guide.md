# Agent SOP: Integrating a New Career Website

When asked to scrape or monitor a new company's career page, an agent must follow this exact sequence of steps to ensure it integrates seamlessly into the existing scalable architecture.

## Step 1: Reconnaissance (Find the JSON)
Before writing any scraper code, **do not** assume standard HTML parsing (like BeautifulSoup or XPath) will work. Modern career pages use dynamically embedded Applicant Tracking Systems (ATS).
*   **Action:** Fetch the raw HTML of the careers URL. Look for `<script>` or `<iframe>` tags pointing to known ATS providers (e.g., `keka.com`, `greenhouse.io`, `lever.co`).
*   **Action:** If the DOM is ambiguous, use the `browser_subagent` to visually load the page and inspect the **Network Tab**. Identify the background `fetch()`/XHR call returning the pure JSON array of active jobs.

## Step 2: Check for Existing ATS Bases
Review the `src/base_ats/` folder.
*   **If the ATS exists** (e.g., Keka): Do not write a new parser. Extract the unique identifier (like the embed UUID) for the new company and prepare to pass it to the existing base function.
*   **If the ATS is new**: Create a new file (e.g., `src/base_ats/greenhouse.py`). This file should contain a single, robust function that takes the company's unique identifier/URL, hits their JSON API, parses it natively, and returns a unified list of job dictionaries. 

## Step 3: Create the Company Wrapper
Create a minimal script inside `src/companies/{company_name}.py`.
*   This script should expose a single `scrape()` function.
*   It is responsible for hitting the company's public careers page, using RegEx to dynamically extract their unique ATS ID/tokens from the HTML, and passing those tokens to the correct `base_ats` function.

## Step 4: Register the Company
Update the master `registry.json` file in the root directory. Add a new object to the `"companies"` array:
```json
{
    "id": "company_name",
    "name": "Company Name",
    "career_url": "https://company.com/careers",
    "base_ats": "ats_name",
    "scraper_module": "src.companies.company_name"
}
```

## Step 5: Validate
Execute the pipeline to ensure the outputs flow correctly into the `outputs/` directory:
*   Run `python main.py --timeframe day` (or `month` for broader testing).
*   Verify that `outputs/{company_id}_<timeframe>_jobs.md` is generated.
*   Verify that `outputs/combined_<timeframe>_jobs.json` successfully appends the new company's payload with normalized dates.

## Step 6: Visual Verification (Crucial)
Do not trust the script output blindly. Always cross-reference the script's output with what a user actually sees:
*   **Action:** Launch the `browser_subagent` to open the target career page.
*   Look at the live job board and count the visible postings (especially those posted within the requested timeframe).
*   Compare the browser agent's visual findings directly against the outputs generated by `main.py`. If the script says `0` but the browser sees `3`, the integration is flawed and the API/Embed parameters must be re-evaluated.

## Step 7: Update the Knowledge Base
If you discover a new ATS platform, or if an existing ATS has fundamentally changed how it embeds data (e.g., shifting from injecting JS variables to making background API calls), you must document it.
*   **Action:** Create or update a markdown file in the `knowledge_base/` directory (e.g., `knowledge_base/greenhouse_insights.md`).
*   Detail the exact payload structure, how to intercept the network calls, and the regex used to dynamically translate the embed link into the API link. This ensures future agents don't have to re-discover the same quirks.
